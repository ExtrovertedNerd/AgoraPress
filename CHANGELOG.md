# Changelog

All notable changes to AgoraPress will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Core currently reports `AP_VERSION` `0.1.0-dev` (see `ap-includes/version.php`).
No tagged public release yet — ship notes accumulate under **[Unreleased]** until the first version is cut.

## [Unreleased]

### Added

- **Template tags, Menus, RSS/Atom, Front-page (Reading) settings:** Front-end template tags in `ap-includes/template-tags.php` (`ap_the_title` / `ap_the_content` / `ap_the_excerpt` / `ap_the_permalink` / `ap_the_date` / `ap_the_author` / `ap_bloginfo` / `ap_body_class`, with get_* variants). Navigation menus (`AP_Nav_Menu`): theme locations, option-backed menus/items (custom URL, page, post, category, tag), assign locations, escaped HTML render; admin screen `ap-admin/nav-menus.php`; procedural helpers `ap_register_nav_menus` / `ap_nav_menu` / `ap_has_nav_menu`. Syndication feeds (`AP_Feed`): RSS 2.0 + Atom at pretty `/feed/` or `?feed=rss2|atom`, item count and full text vs summary from Reading settings; short-circuit in front controller before the theme. Reading settings (`AP_Options` helpers + `ap-admin/options-reading.php`): `show_on_front` / `page_on_front` / `page_for_posts` / `posts_per_page` / `posts_per_rss` / `rss_use_excerpt`; `AP_Rewrite::applyReadingSettings()` maps home → static page or latest posts and posts-page → blog index; Agora theme uses `front-page.php`, primary/footer menus, and RSS alternate links. Installer seeds Reading + empty menu options. Tests: `tests/Template/TemplateTagsTest.php`, `tests/Menu/NavMenuTest.php`, `tests/Feed/FeedTest.php`, `tests/Options/ReadingSettingsTest.php`, `tests/test_template_tags_menus_rss.py`.
- Default theme **Agora** polish: lightweight image-free pure CSS with **exactly six color schemes** (3 light + 3 dark) — Marble, Parchment, Cloud, Obsidian, Midnight, Charcoal — selectable via Theme Options (`ap-admin/theme-options.php`) and option `agora_color_scheme` (default `marble`). Scheme API in `ap-content/themes/agora/functions.php` (`agora_get_color_schemes`, `agora_get/set_color_scheme`, `agora_body_class`); body classes `agora-scheme-{slug}` + `agora-mode-light|dark`; accessible typography, sticky header, cards, focus rings, print + reduced-motion styles. Installer seeds `agora_color_scheme`. Admin menu item “Theme Options”. Tests: `tests/Theme/AgoraThemeTest.php`, `tests/test_agora_theme.py`.
- Front-end template loader + classic hierarchy (`AP_Theme` + `ap_*` helpers): active theme via `stylesheet` / `template` options (default `agora`), style.css header parsing and theme discovery, child→parent template location, WordPress-inspired hierarchy from `AP_Query` conditionals (home, single, page + custom page templates, category/tag/tax, author, date, search, 404, archives), `get_header` / `get_footer` / `get_sidebar` partials, `functions.php` load (parent then child), and `render()` / `ap_template_loader()` wired from front controller `index.php`. Ships a functional default theme under `ap-content/themes/agora/` (index, single, page, home, archive, search, 404, category/tag/author, example Full Width page template; color-scheme polish listed separately above). Installer seeds `stylesheet`/`template`. Tests: `tests/Theme/ThemeLoaderTest.php`, `tests/test_theme_loader.py`.
- Permalinks / rewrite rules (`AP_Rewrite` + `ap_*` helpers): pretty URL structures (Plain, Day and name, Month and name, Numeric, Post name, custom tags `%year%` `%monthnum%` `%day%` `%post_id%` `%postname%` `%category%` `%author%`), optional `category_base` / `tag_base`, rule generation + flush into options (`rewrite_rules`), `parseRequest` / `parseFromGlobals` path → query vars for `AP_Query`, link builders for posts/pages/terms/authors/search/home/site, Apache/Nginx front-controller snippets. Front controller `index.php` parses the request and sets the main query. Installer seeds `permalink_structure`, `category_base`, `tag_base`, `rewrite_rules`. Admin post edit shows the computed permalink. Root `.htaccess` and `docker/nginx.conf.example` document pretty-permalink routing. Tests: `tests/Rewrite/RewriteTest.php`, `tests/test_rewrite.py`.
- Comments + moderation (`AP_Comment` + admin): migration `0004_core_comments_commentmeta.php` creates `{prefix}comments` and `{prefix}commentmeta` (MySQL/SQLite/PostgreSQL). Nested threads via `comment_parent`; statuses `1` (approved) / `0` (pending) / `spam` / `trash`; approve/unapprove/spam/unspam/trash/untrash/delete with `posts.comment_count` sync; pluggable spam checkers (`registerSpamChecker` + future `ap_pre_comment_approved` filter); commentmeta CRUD; query/list, status counts, and nested `getTree()`. Procedural helpers: `ap_insert_comment`, `ap_approve_comment`, `ap_get_comment_tree`, `ap_register_comment_spam_checker`, etc. Admin: `edit-comments.php` list with All/Pending/Approved/Spam/Trash views, search, bulk + row moderation actions, Comments menu item. `AP_DB_VERSION` bumped to `4`. Tests: `tests/Comment/CommentModelTest.php`, `tests/Database/CommentsCommentmetaMigrationTest.php`, `tests/Admin/AdminCommentsTest.php`, `tests/test_comments.py`.
- Taxonomies (`AP_Taxonomy` + admin): migration `0003_core_terms_taxonomies.php` creates `{prefix}terms`, `{prefix}term_taxonomy`, `{prefix}term_relationships` (MySQL/SQLite/PostgreSQL). Built-in `category` (hierarchical) and `post_tag` (flat); registerable custom taxonomies; term CRUD with unique slugs, hierarchy + cycle prevention, default Uncategorized category; object relationships (`setObjectTerms` / `getObjectTerms`) with auto-create for tag names and count maintenance. `AP_Query` supports `cat`, `category_name`, `category__in`/`__not_in`/`__and`, `tag` / `tag_id` / `tag__*`, `tax_query` (EXISTS subqueries), and `is_category` / `is_tag` / `is_tax` flags. Procedural helpers: `ap_register_taxonomy`, `ap_insert_term`, `ap_set_post_categories`, `ap_set_post_tags`, etc. Admin: `edit-tags.php` list/add/edit/delete for Categories & Tags, menu items, post edit sidebar checklist + tags input, list table Categories/Tags columns and `?cat=` category filter. `AP_DB_VERSION` bumped to `3`. Tests: `tests/Taxonomy/TaxonomyTest.php`, `tests/Database/TermsTaxonomyMigrationTest.php`, `tests/test_taxonomies.py`, extended `AdminPostsTest`.
- Media Library (`AP_Media` + admin): secure multi-file uploads into `ap-content/uploads/` (optional year/month folders), allow-listed MIME/extension checks with `finfo` content sniffing and executable rejection, attachment posts (`post_type=attachment`, status `inherit`) with meta for relative path, filesize/dimensions, and image alt text; query/list by search, MIME group, and date; permanent delete removes DB row + file. Upload dir hardening writes `.htaccess` (static media allowed, script extensions denied) + silent `index.php` on first use. Procedural helpers: `ap_handle_upload`, `ap_insert_attachment`, `ap_delete_attachment`, `ap_get_attachment_url`, `ap_upload_dir`, etc. Admin: `upload.php` (grid/list toggle, multi-file + drag-and-drop upload, bulk delete, MIME/date/search filters), `media.php` attachment details (title, caption, alt, description, file URL), Media menu item. Tests: `tests/Media/MediaLibraryTest.php`, `tests/test_media_library.py`.
- Post revisions + autosave (`AP_Post` + admin): revision rows (`post_type=revision`, `post_status=inherit`, `post_parent` = parent ID) snapshot title/content/excerpt on update when the type supports `revisions`; max kept via `AP_POST_REVISIONS` / `DEFAULT_MAX_REVISIONS` with `pruneRevisions()`; one autosave per author (`{id}-autosave-{userId}`) that does not mutate the parent; restore / delete / list / count APIs; force-delete parent removes child revisions. Procedural helpers: `ap_save_post_revision`, `ap_autosave_post`, `ap_get_post_revisions`, `ap_restore_post_revision`, `ap_get_post_autosave`, etc. Admin: Autosave button on edit form, Revisions metabox, history screen `ap-admin/revision.php` with restore/delete. Tests: extended `PostModelTest` / `AdminPostsTest`, pytest smokes.
- Admin list tables + edit screens for Posts and Pages (`ap-admin/`): login (`login.php`), dashboard (`index.php`), list table (`edit.php?post_type=post|page`) with status views (All/Published/Draft/Pending/Private/Scheduled/Trash), search, pagination, bulk trash/untrash/delete/status change, row actions; create/edit screens (`post-new.php`, `post.php`) with title, slug, content, excerpt, status/visibility (public/password/private), publish date, sticky (posts), page attributes (parent, order, template), discussion checkbox; nonces on all state-changing forms (`AP_Nonce` + `ap_create_nonce` / `ap_check_nonce` / `ap_nonce_field`); escaping helpers (`ap_esc_html`, `ap_esc_attr`, `ap_sanitize_text_field`); lightweight accessible admin CSS (light/dark via `prefers-color-scheme`). Capability checks remain open to any logged-in user until Phase 3 roles. Tests: `tests/Admin/AdminPostsTest.php`, `tests/test_admin_posts.py`.
- Post statuses, types, hierarchical pages (`AP_Post` + `ap_*` helpers): built-in statuses (publish, draft, pending, private, future, trash, auto-draft, inherit) and types (post, page, revision, attachment); lightweight custom status/type registration; insert/update/trash/untrash/delete with unique slugs, future auto-schedule, password protection, sticky + page-template meta; hierarchical pages (`post_parent`, ancestors, page path, tree, cycle prevention, re-parent on force-delete); simple list query and postmeta helpers. Bootstrap loads `class-ap-post.php` and registers builtins. Tests: `tests/Post/PostModelTest.php`, `tests/test_post_model.py`.
- Core tables migration `0002_core_posts_postmeta.php`: creates `{prefix}posts` and `{prefix}postmeta` with multi-driver DDL (MySQL/MariaDB InnoDB utf8mb4, SQLite, PostgreSQL). Posts hold author, dates (local + GMT), content/title/excerpt, status, comment/ping flags, password, slug (`post_name`), hierarchy (`post_parent`), GUID, menu order, type (post/page/revision/attachment/CPT), mime type, and comment count — indexes on name, type+status+date, parent, and author. Postmeta is key/value by `post_id`. `AP_DB_VERSION` bumped to `2`. Tests: `tests/Database/PostsPostmetaMigrationTest.php`, extended Migrator suite + pytest.
- “Already installed” protection: `AP_Installer::configExists()` / `alreadyInstalledMessage()`; `writeConfigFile()` and `run()` refuse to overwrite an existing config; web installer (`install/index.php`) returns HTTP 403 with an “Already installed” screen when `ap-config.php` is present (post-install success screen only when the same session just finished install — no `?step=done` loophole); CLI exits early with code 3 before requirements/DB work. Tests: `InstallerTest`, `InstallUiTest`, `CliInstallTest`, `tests/test_installer.py`.
- CLI install path (`install/cli.php` + `AP_Cli_Install`): non-interactive install sharing `AP_Installer` / `AP_Requirements` with the web flow — flags for DB driver (mysql/sqlite/pgsql), credentials, table prefix, site title/URL, admin account; env fallbacks `AP_ADMIN_PASSWORD` / `AP_DB_PASSWORD`; requirements check (optional `--skip-requirements`); refuses existing `ap-config.php`; exit codes 0/1/2/3. Documented under README Option C. Tests: `tests/Install/CliInstallTest.php`, `tests/test_cli_install.py`.
- Session handling (`AP_Session` + `ap_*` helpers): signed HMAC-SHA256 auth cookies (`user_id|expiration|token|hmac`) using `AP_LOGGED_IN_KEY` + `AP_LOGGED_IN_SALT`, HttpOnly / SameSite=Lax / Secure-when-HTTPS, default 2-day lifetime (14 days with “remember me”), per-session tokens stored hashed in usermeta (`session_tokens`) for server-side revoke, `login` / `logout` / `setAuthCookie` / `clearAuthCookie` / `getCurrentUser` / `isLoggedIn`. Password changes via `AP_User::updatePassword()` destroy all session tokens and bind cookies to a password-hash fragment so outstanding cookies fail validation. Procedural API: `ap_login`, `ap_logout`, `ap_set_auth_cookie`, `ap_clear_auth_cookie`, `ap_is_user_logged_in`, `ap_get_current_user`, `ap_get_current_user_id`, `ap_auth_cookie_name`, `ap_destroy_user_sessions`. Bootstrap loads the session layer after users. Tests: `tests/User/SessionTest.php`, `tests/test_session.py`.
- Basic authentication (`AP_User` + `ap_*` helpers): Argon2id password hashing when `PASSWORD_ARGON2ID` is available (fallback `PASSWORD_DEFAULT`), `password_verify` checks, transparent rehash on successful login, user lookup by id/login/email/nicename, and `authenticate(login|email, password)` against `{prefix}users` (rejects inactive `user_status !== 0`; dummy-hash path for unknown accounts). Procedural API: `ap_hash_password`, `ap_check_password`, `ap_password_needs_rehash`, `ap_authenticate`, `ap_get_user_by`. Installer seed hashing delegates to `AP_User`. Bootstrap loads the user class after the DB layer. Tests: `tests/User/UserAuthTest.php`, `tests/test_user_auth.py`.
- Web installer (`install/index.php`): multi-step flow **requirements → database → site info + admin → tables + config**. `AP_Requirements` checks PHP 8.2+, required extensions (PDO driver, mbstring, json, curl, fileinfo, zip, gd|imagick), recommended intl, and writable site root / `ap-content` / uploads. `AP_Installer` generates unique auth salts, writes `ap-config.php` (never commit), runs versioned migrations, seeds core options (including module toggles) and the first administrator with Argon2id password hashing. Supports mysql/sqlite/pgsql; refuses to overwrite an existing config. Bootstrap “not installed” page links to `/install/`. Tests: `tests/Install/`, `tests/test_installer.py`.
- Core tables migration `0001_core_options_users.php`: creates `{prefix}options`, `{prefix}users`, and `{prefix}usermeta` with multi-driver DDL (MySQL/MariaDB InnoDB utf8mb4, SQLite, PostgreSQL). Options include `option_name` / `option_value` / `autoload`; users hold login, Argon2id-ready `user_pass`, email, nicename, status, display name; usermeta is key/value by `user_id`. `AP_DB_VERSION` bumped to `1`. Tests: `tests/Database/CoreTablesMigrationTest.php`, extended Migrator suite + pytest.
- Versioned schema / migration system (`ap-includes/class-ap-migrator.php`, `AP_Migration`, `schema/migrations/`): discovers numbered `NNNN_slug.php` migrations, tracks applied versions in `{prefix}schema_migrations`, applies pending upgrades in order (`migrate()` / `pending()` / `needsMigration()`), honors table prefix and multi-driver registry DDL (mysql/sqlite/pgsql). Bootstrap loads the migrator without auto-running migrations. Tests: `tests/Database/MigratorTest.php`, `tests/test_migrator.py`
- Table prefix support: configurable `$table_prefix` (default `ap_`) normalized to a safe SQL fragment, exposed as `AP_TABLE_PREFIX` / `ap_get_table_prefix()`; Docker `AP_TABLE_PREFIX` env honored when config omits `$table_prefix`. Core + forum base table lists (`ap_core_base_tables`, `ap_forum_base_tables`, `ap_all_base_tables`) and helpers `ap_prefixed_table()` / `ap_prefixed_tables()`. `AP_DB` normalizes prefixes, applies them in `table()` / insert/update/delete, exposes WP-style `$apdb->options`/`$apdb->users`/… properties, `setPrefix()`, `tables()`, `resolveConfiguredPrefix()`. Tests: `tests/Database/TablePrefixTest.php`, extended Config/Database suites + pytest.
- Database abstraction (`ap-includes/class-ap-db.php`): `AP_DB` / global `$apdb` via lazy `ap_db()`, PDO only with real prepared statements (`ATTR_EMULATE_PREPARES` off), drivers mysql/sqlite/pgsql (DSN builder, host:port), prefixed `table()`, `query`/`getVar`/`getRow`/`getCol`/`getResults`, `insert`/`update`/`delete` with bound values, transactions, `AP_DB_Exception`. Bootstrap loads the class without connecting. Tests: `tests/Database/DatabaseTest.php`, `tests/test_database.py`
- Config loading (`ap-includes/load-config.php`): load/validate `ap-config.php`, required constants, defaults (charset, debug, telemetry off), table-prefix normalize + `AP_TABLE_PREFIX` / `ap_get_table_prefix()`, content path constants, debug error settings; incomplete/invalid config returns friendly 503 HTML. Wired from bootstrap via `ap_load_config()`. Tests: `tests/Config/ConfigLoadTest.php`, `tests/test_config_load.py`
