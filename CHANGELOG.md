# Changelog

All notable changes to AgoraPress will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Core currently reports `AP_VERSION` `0.1.0-dev` (see `ap-includes/version.php`).
No tagged public release yet — ship notes accumulate under **[Unreleased]** until the first version is cut.

## [Unreleased]

### Added

- **Hall of Fame (voluntary domain registration only — no telemetry):** Chose Hall of Fame over anonymous installer pings. Core `AP_Hall_Of_Fame` never runs during install or ordinary requests; join/leave are explicit `manage_options` actions with nonces. Registration payload is domain + action only (withdrawal token on leave) — no email, user id, or environment fingerprint. Local options track membership; dashboard shows an opt-in prompt (dismissible without contacting the project site); Settings → Hall of Fame for join/leave + unobtrusive donation-footer toggle (default on). Installer seeds empty membership and does not phone home. Procedural helpers: `ap_hall_of_fame_is_joined` / `ap_hall_of_fame_status` / `ap_show_donation_button` / `ap_hall_of_fame_domain`. Tests: `tests/Admin/HallOfFameTest.php`, `tests/test_hall_of_fame.py`.
- **Nonces on all forms (CSRF):** Core `AP_Nonce` (HMAC-SHA256, 12h ticks + previous-tick grace) already gated every state-changing admin POST (posts/pages, terms, comments, media, users/profile, settings groups, nav menus, theme options, quick draft, login/register/lost-password/reset). Extended API: `ap_nonce_url` / `AP_Nonce::url` for GET action links, `ap_verify_request_nonce` / `ap_check_request_nonce` (accepts `_ap_nonce` and `_wpnonce` alias). Admin **Log out** is nonce-protected (`log-out` action; header uses `ap_nonce_url`). Installer keeps session `ap_csrf` tokens (no salts before `ap-config.php`). Form-audit + unit tests: `tests/Security/NonceTest.php`, `tests/test_nonces.py`.
- **Dashboard home with stats:** Admin `index.php` is a real At a Glance / Activity / Quick Draft home. `AP_Admin_Dashboard` aggregates module-aware counts (published/draft/pending posts & pages, approved+pending comments, users), recent published content, and recent comments; forum slot is reserved (“Coming soon” when Forum is enabled until Phase 5 tables exist). Quick Draft saves a draft post with nonce + `edit_posts` gates when Blog is on. Cards and layout use responsive CSS (`ap-dashboard-grid`, glance list, activity list). Tests: `tests/Admin/AdminDashboardTest.php`, `tests/test_admin_dashboard.py`.
- **Settings API + core settings screens:** WordPress-inspired Settings API (`AP_Settings` + `ap_register_setting` / `ap_add_settings_section` / `ap_add_settings_field` / `ap_settings_fields` / `ap_do_settings_sections`) with option-group registration, sanitize callbacks, section/field rendering, nonce-backed group save, and error queue. Core groups: general, modules, writing, reading, discussion, media, permalink (`registerCore()` on bootstrap). Admin screens: `options-general.php` (title, tagline, URLs, admin email, membership, default role, timezone/date/time), `options-modules.php` (three independent Static Pages / Blog / Forum toggles; at least one required), `options-writing.php`, existing `options-reading.php` (Settings API nonces), `options-discussion.php` (comments + avatars), `options-media.php` (image sizes + year/month folders), `options-permalink.php` (structure presets + category/tag bases). Helpers on `AP_Options` (`isModuleEnabled` / `updateModules` / `updateGeneralSettings` / …); `AP_Media::useYearMonthFolders()` honors `uploads_use_yearmonth_folders`; admin menu lists all settings screens and hides Blog/Pages items when modules are off. Installer seeds discussion/media/writing defaults. Tests: `tests/Options/SettingsApiTest.php`, `tests/test_settings_api.py`.
- **Capability checks on all admin screens:** Every privileged `ap-admin` entry point calls `AP_Admin::requireCapability()` after login (`read` shell gate remains). Screen map: Posts/Pages list+new (`edit_posts`/`edit_pages`), post/revision edit (`edit_post`/`edit_page` meta), Comments (`moderate_comments`), Categories/Tags (`manage_categories`), Media (`upload_files`), Users (`list_users`/`create_users`/`edit_users`), Theme Options + Menus (`edit_theme_options`), Reading (`manage_options`), Profile/Dashboard (`read`). Handlers enforce the same caps (and meta-caps for own vs others): post save/row/bulk, media upload/save/delete, comment moderation, term CRUD. Contributors without `publish_*` are forced to `pending` instead of published. Helpers: `AP_Admin::userCan`, `editCapabilityForPostType`, `editMetaCapForPostType`, `deleteMetaCapForPostType`, `publishCapabilityForPostType`, `screenCapabilities`. Tests: `tests/Admin/AdminCapabilityTest.php`, `tests/test_admin_capabilities.py`.
- **Avatars (local upload + Gravatar):** `AP_Avatar` resolves custom uploads (usermeta `ap_avatar` → attachment) then Gravatar by email, with site options `show_avatars` / `avatar_default` / `avatar_rating` (seeded by installer). Local uploads via `AP_Media` (JPG/PNG/GIF/WebP, 2 MiB cap); remove + replace; user delete cleans avatar files. Procedural API: `ap_get_avatar` / `ap_get_avatar_url` / `ap_get_avatar_data` / `ap_upload_user_avatar` / `ap_delete_user_avatar` / `ap_show_avatars`. Template tags `ap_the_author_avatar` / `ap_get_the_author_avatar`. Admin profile & Edit User: multipart form, avatar preview, file input, remove checkbox; users list shows 32px avatars. Offline mystery-person SVG data URI when default is mystery and no email. Tests: `tests/User/AvatarTest.php`, `tests/test_avatars.py`.
- **Registration, email verification, password reset:** Public self-registration gated by option `users_can_register` (installer default off); optional email verification via `require_email_verification` (default on) creates accounts with `user_status=1` until confirmed. HMAC one-time keys in `user_activation_key` (purpose:timestamp:hmac, 24h TTL) for verify + reset links; password-reset emails never leak account existence; 60s per-account reset cooldown; successful reset revokes sessions via `AP_User::updatePassword`. Core: `AP_Registration`, `AP_Mail` (test outbox), procedural helpers `ap_register_user` / `ap_verify_user_email` / `ap_request_password_reset` / `ap_check_password_reset_key` / `ap_reset_password` / `ap_mail` / `ap_users_can_register` / `ap_require_email_verification`. UI: `ap-admin/login.php` actions `register`, `lostpassword`, `rp`, `verifyemail` with nonces; pending-user login message. Tests: `tests/User/RegistrationTest.php`, `tests/test_registration.py`.
